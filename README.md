# mrz-check

Offline parser and check-digit validator for the **machine-readable zone (MRZ)** of passports and ID cards, following **ICAO Doc 9303**:

| Format | Documents | Layout |
|---|---|---|
| TD3 | Passports | 2 × 44 |
| TD2 | Older ID cards, visas | 2 × 36 |
| TD1 | ID cards | 3 × 30 |

It is a small, dependency-free version of the MRZ validation step in the self-hosted KYC pipeline I built at [Sealify](https://sealify.io), where ID/passport data is checked before face matching instead of sending it to a paid KYC provider. It is written from scratch as an independent tool and does not contain Sealify code. Everything runs locally, no network, nothing stored.

## What it checks
- Every check digit: document number, birth date, expiry date, personal number (TD3) and the **composite** check digit
- Long document numbers that continue into the optional data field (TD1 / TD2)
- Real calendar dates for birth and expiry, valid sex field, allowed characters and line lengths
- Whether the document has expired

```bash
pip install git+https://github.com/LeventCeliksan/mrz-check
```

## Usage
```bash
mrz-check 'P<UTOERIKSSON<<ANNA<MARIA<<<<<<<<<<<<<<<<<<<' 'L898902C36UTO7408122F1204159ZE184226B<<<<<10'
# TD3 P UTO  ERIKSSON, ANNA MARIA
# document L898902C3  nationality UTO  born 1974-08-12  sex F  expires 2012-04-15  (EXPIRED)
#   OK  document_number  expected 6 found 6
#   ...
# VALID
```
Lines can also come from stdin (e.g. OCR output); `--json` prints the full result. Exit codes: `0` valid, `1` a check failed, `2` not an MRZ.

```python
from mrz_check import parse
r = parse(ocr_text)
if not r.valid:
    print([c.field for c in r.checks if not c.ok], r.errors)
```

## Tests
```bash
pip install -e ".[test]"
pytest
```
The suite uses the ICAO 9303 specimen documents for all three formats, flips every single digit of a passport MRZ to prove each change is caught, builds long-document-number cases, and cross-checks 300 random passport MRZs generated by an independent library ([`mrz`](https://pypi.org/project/mrz/)).

## Note
Check digits catch typing and OCR errors; they are not a security feature, since anyone can compute them. In a real KYC flow this is one step next to chip (NFC) reading, document forensics and face matching.
